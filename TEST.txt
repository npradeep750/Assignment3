# WHAT WAS CHANGED TO IMPROVE THE POOR QUERIES
# 1. Length normalization (cosine similarity). Each page's score is divided by the length of its tf-idf vector,
#    so a long page does not win just because it has more words. At first this was full strength, but then very
#    short pages like slides took over many results, so the strength was lowered with NORMS_POWER = 0.5 in search.py.
# 2. Partial-match fallback. Pages with all query words are listed first. If fewer than 5 have them all, pages with
#    some of the words fill the rest. A word that is not in the index (typo) is skipped instead of making the whole
#    query return nothing.
# 3. Speed: each query word's postings are read straight from index.txt with a seek (the index is never loaded into
#    memory), the AND starts from the shortest postings list, and long postings lists are parsed in bulk.
# 4. Exact duplicate pages are skipped while indexing.
#
# EFFICIENCY: no query took longer than 300 ms. The slowest ones use very common words ("the and or", "to be or not
#    to be", "master of software engineering") because the postings lists of those words are huge.
